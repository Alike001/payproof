# PayProof Builder Profile

Recorded: 2026-09-01.

## Team

- Two-person team.
- Abu expects to implement most of the product.
- The second contributor will work through pull requests.
- Abu will review the contributor's code before merging to the main branch.
- AI-assisted development is expected throughout the build.

## Working Style

- Comfortable multitasking and prepared to devote substantial time before the
  deadline.
- The build plan should use focused work blocks and protect review/testing time;
  it should not depend on repeated 20-hour workdays.
- Technology choices should follow the product and verification requirements,
  rather than an existing stack preference.

## Participant's Product Framing

PayProof is an invoice application where freelancers create invoices in local
currencies, clients see and pay the converted amount in USDC on Base, and the
application verifies the transaction and issues a receipt. The product removes
the need for either party to trust a payment screenshot.

The most exciting part for the participant is making local-currency pricing and
USDC payment work together simply.

## Initial User Access

- No established tester group yet.
- Friends and acquaintances can be invited directly.
- Social-media posts and WhatsApp Status will be used to recruit testers.
- The intended market is broad, but the launch wedge should be remote
  freelancers receiving cross-border payments, with Nigerian freelancers as
  the most reachable first cohort.

## Planning Calibration

- Explain product and technical decisions in plain language.
- Keep the first-use journey obvious within 30 seconds.
- Require real Telegraph calls and fail visibly when intelligence is
  unavailable.
- Optimize for a working end-to-end product and genuine tester evidence, not a
  broad feature list.
